Hallo zusammen,

„Hauptsache, es läuft“ reicht oft nur bis zur nächsten Änderung. Spätestens dann zeigt sich, ob Code verständlich und gut wartbar ist.

In unserer Live-Session diese Woche geht es um Code-Qualität und Refactoring: Wie verbessern wir bestehenden Code, ohne dabei etwas kaputt zu machen? Dazu räumen wir gemeinsam ein gewachsenes Auswertungsskript für Verkaufsdaten Schritt für Schritt auf.

Auf dem Programm stehen:

Code Smells erkennen: Was macht Code schwer lesbar?
PEP 8: der offizielle Style Guide für Python
Sprechende Namen und Konstanten statt fester Zahlenwerte
Wiederholungen entfernen und Code in Funktionen aufteilen
Nach jedem Schritt prüfen, dass das Ergebnis gleich bleibt
Refactoring oder Verhaltensänderung? Warum man beides trennt


Die Session bildet den Abschluss der Basics und wendet die Inhalte aller vorherigen Sessions an. Bringt gerne eure Fragen mit, und gerne auch eigenen Code, den ihr schon immer mal aufräumen wolltet.
